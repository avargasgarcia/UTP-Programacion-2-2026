El parámetro es una copia

int main(void)
{
    int x, y;

    x = 5;
    y = duplicar(x);
    printf("x = %d, y = %d\n", x, y);
    return 0;
}

int duplicar(int n)
{
    n = n * 2;
    return n;
}
x = 5, y = 10
main
x5
y10
duplicar
n5 → 10
Paso por valor
  • La llamada entrega el valor de x (5), no la variable.
  • n es una variable nueva que nace con esa copia.
  • Cambiar n no cambia x.
  • Para que main tenga el nuevo valor, recíbalo: y = duplicar(x);

Programa: copia.c.

Argumentos y parámetros

Se emparejan por posición, no por nombre

double precio_final(double precio, int descuento);

int main(void)
{
    printf("Bien:     %.1f\n", precio_final(50000, 10));
    printf("Al reves: %.1f\n", precio_final(10, 50000));
    return 0;
}

double precio_final(double precio, int descuento)
{
    return precio - precio * descuento / 100.0;

Ámbito y tiempo de vida

Cada función tiene sus propias variables

int main(void)
...
    for (i = 1; i <= 4; i++) {
        printf("i = %d, suma_hasta(i) = %d\n", i, suma_hasta(i));
    }
    printf("Al salir del ciclo, i = %d\n", i);
...
int suma_hasta(int n)
{
    int i, s = 0;

    for (i = 1; i <= n; i++) {
        s = s + i;
    }
    return s;
}
i = 1, suma_hasta(i) = 1
i = 2, suma_hasta(i) = 3
i = 3, suma_hasta(i) = 6
i = 4, suma_hasta(i) = 10
Al salir del ciclo, i = 5
Variables locales
  • Se declaran dentro de una función; solo esa función las ve.
  • Nacen al llamar y desaparecen al volver: la i de suma_hasta empieza de nuevo en cada llamada.
  • Dos i con el mismo nombre: dos variables distintas. La de main sigue contando.
¿Y las globales?

Se declaran fuera de toda función y cualquiera puede cambiarlas: cuando un valor sale mal, hay que revisar todo el programa. En este curso no se usan (las constantes van con #define).

int leer_entero_en_rango(int min, int max)
{

 Bloque D · cápsula 6.4

  
Diseño descendente: de lo grande a lo pequeño

  

  

    
1 · ¿Qué hace el programa?
«Lee tres notas, calcula la definitiva (30 %, 30 %, 40 %) e informa si aprueba.» Eso es main.

    
2 · Partir en tareas
Leer una nota válida · calcular la definitiva · imprimir el informe. Cada tarea, una función.

    
3 · ¿Cabe en una función corta?
Si no, se parte otra vez: el informe necesita saber si aprueba → aprueba.

  







  
 Cohesión y acoplamiento, en la práctica

  
Tres reglas de una buena función

  

    

      Las reglas
      
    
        
  1. Una sola tarea (cohesión). Su nombre es un verbo: leer_nota. Si necesita una «y» para describirla, son dos funciones.
    2. 
        
  2. Solo parámetros y return (poco acoplamiento). Lo que entra, en los paréntesis; lo que sale, en el return. Nada de globales.
    3. 
        
  3. Lo copiado y pegado es una función. Si escribió dos veces el mismo bloque, los datos que cambian son sus parámetros.
    4. 
      

      
A la derecha, la regla 2: las dos versiones imprimen Total: 3800.0, pero en la segunda la llamada muestra qué cambia.

    

    

      

        Con una global
        
double total = 0.0;            /* global */
...
void agregar(double valor)
{
    total = total + valor;
}

      

      

        Con parámetros
        
    total = agregar(total, 1500.0);
...
double agregar(double total, double valor)
{
    return total + valor;
}
