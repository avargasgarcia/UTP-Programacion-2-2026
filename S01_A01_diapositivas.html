Concepto 1 de 3

¿Qué es un paradigma de programación?

Un modelo de cómputo —una idea formal de qué significa calcular— junto con el conjunto de conceptos y reglas con los que se organiza y se expresa la solución.

Modelo del paradigma funcional

Cálculo lambda

Calcular es reducir una expresión hasta su forma más simple. No hay tiempo ni memoria: hay sustitución.

Church, 1936

Modelo del paradigma imperativo

Máquina de estados

Calcular es ejecutar instrucciones que modifican una memoria. El programa avanza en el tiempo, celda por celda.

Turing, 1937 · von Neumann, 1945

Los dos modelos son equivalentes en poder de cómputo: lo que se puede calcular en uno se puede calcular en el otro. Cambia cómo se expresa la solución, no qué problemas se pueden resolver.

Concepto 2 de 3 · el que usted ya practicó

El paradigma funcional describe qué es el resultado

Rasgos
  • Función pura: el resultado depende solo de los argumentos
  • Transparencia referencial: la misma llamada siempre da el mismo valor
  • Inmutabilidad: los datos no se modifican, se construyen otros
  • Recursión en lugar de ciclos
suma.rktRacket 8.10 · verificado
; La suma se DEFINE, no se calcula paso a paso
(define (suma lista)
  (if (null? lista)
      0
      (+ (car lista) (suma (cdr lista)))))

(suma '(4 8 15 16 23 42))  ; => 108

Herencia directa de LISP (McCarthy, 1960) y de Scheme (Sussman y Steele, 1975).

Concepto 3 de 3 · el que empieza hoy

El paradigma imperativo describe cómo llegar al resultado

Rasgos
  • Estado: el conjunto de valores que las variables tienen ahora
  • Asignación destructiva: escribir un valor borra el anterior
  • Secuencia: el orden de las instrucciones cambia el resultado
  • Efectos secundarios: una instrucción puede alterar algo fuera de sí misma
suma.cgcc -std=c99 -Wall -Wextra · verificado
int suma(const int v[], int n)
{
    int acumulador = 0;            /* estado inicial */
    for (int i = 0; i < n; i++) {
        acumulador = acumulador + v[i];  /* cambia */
    }
    return acumulador;              /* estado final */
}

C nació en los Laboratorios Bell sobre un PDP-11; «a comienzos de 1973 lo esencial del C moderno estaba completo» (Ritchie, 1993).

El mismo problema, los dos paradigmas

Sumar la lista 4 · 8 · 15 · 16 · 23 · 42

Funcional · Racket 
(define (suma lista)
  (if (null? lista)
      0
      (+ (car lista)
         (suma (cdr lista)))))
  • Ninguna variable cambia de valor
  • El caso base 0 define el resultado de la lista vacía
  • La solución se compone con la del resto de la lista
Imperativo · C99 
int acumulador = 0;
for (int i = 0; i < n; i++) {
    acumulador = acumulador + v[i];
}
return acumulador;
  • Dos variables cambian: i y acumulador
  • El valor inicial 0 es un estado, no una definición
  • El resultado se acumula repitiendo una instrucción
Ambos entregan 108. La diferencia no está en el resultado: está en qué ocurre mientras se calcula.

Cierre · qué aprendimos

Tres ideas y tres preguntas

Qué aprendimos
  • Un paradigma es un modelo de cómputo más una forma de expresar la solución
  • Lo funcional define el resultado; lo imperativo transforma un estado hasta obtenerlo
  • Son equivalentes en poder de cómputo: cambia la forma de razonar, no lo que se puede resolver
Autoevaluación

1 · ¿Por qué x = x + 1 no es una ecuación?

Porque no afirma una igualdad: ordena calcular x + 1 y sobrescribir con ese valor la celda x. Como ecuación no tendría solución.

2 · ¿Qué le falta a una función para ser pura?

Depender de algo distinto de sus argumentos, o modificar algo fuera de sí misma: en ambos casos pierde la transparencia referencial.

3 · Si son equivalentes, ¿por qué estudiar los dos?

Porque la equivalencia es teórica. En la práctica cada modelo hace fácil un tipo de problema y difícil el otro: el hardware es una máquina de estados, y el razonamiento matemático es funcional.
