Repaso de la semana 3

if e if-else en una diapositiva

Decisión simple 
if (condición) {
    instrucciones;
}
/* si es falsa, sigue aquí */

Solo hay algo que hacer cuando se cumple. La rama No va directa al punto de reunión.

Decisión compuesta 
if (condición) {
    instrucciones del Sí;
} else {
    instrucciones del No;
}

Uno de dos bloques, nunca los dos. else no lleva condición.

Las tres reglas que siguen en pie
  • La condición entre paréntesis y sin ; después del paréntesis.
  • == para comparar; = guarda un valor.
  • Llaves siempre, aunque el bloque tenga una sola línea.

Los reales no se comparan con ==

 Trampa 3

  
Condiciones que compilan y mienten

  

    

      
/* Se queria: x entre 1 y 9. Con || es verdadera para cualquier x. */
if (x > 0 || x < 10) {
...
if (x > 0 && x < 10) {
...
/* En C, cualquier valor distinto de 0 es verdadero. */
if (x) {

      

        
x: 25
Con ||: dentro del rango
Con &&: fuera del rango
if (x): verdadero

        
x: 0
Con ||: dentro del rango
Con &&: fuera del rango
if (x): falso

      

    

    

      Dos lecciones
      
Un rango se escribe con &&. Con ||, todo número cumple al menos una parte: 25 no es menor que 10, pero sí es mayor que 0. La condición es siempre verdadera, y gcc no lo avisa.

      
En C, distinto de 0 es verdadero. if (x) significa if (x != 0). Es válido, pero en el curso se escribe la comparación completa: se lee mejor.

Bloque B · Cápsula 4.3

  
La escalera else if
y las decisiones anidadas

  
En la cápsula 2.4 usted dibujó la escalera de rombos y los rombos anidados. Hoy los escribe en C: el orden de las condiciones, cuándo anidar, el else colgante y cómo probar una escalera.







  
 Del diagrama al código

  
Si · Sino Si · Sino → if · else if · else

  

    

    

      

        

          Pseudocódigo
          
Si cond1 Entonces
   bloque 1
Sino Si cond2 Entonces
   bloque 2
Sino
   bloque 3
FinSi

        

        

          C
          
if (cond1) {
    bloque 1;
} else if (cond2) {
    bloque 2;
} else {
    bloque 3;
}

        

      

      
    
        
  • Se evalúa de arriba hacia abajo: la primera condición verdadera gana; las siguientes ni se miran.
    • 
        
  • Por eso cada condición puede dar por hecho que todas las anteriores fueron falsas.
    • 
        
  • El else final no lleva condición: recoge todo lo demás.
    • 
        
  • else if son dos palabras, en la misma línea de la } anterior.
    •

 Decisiones anidadas

  
Una decisión dentro de otra

  

    

      
«Para subir a la atracción hay que medir al menos 120 cm. A quien cumple, se le pregunta la edad: con 12 o más sube solo; si no, con un adulto.» (Reglas del ejemplo.)

      
if (estatura >= ESTATURA_MINIMA) {
    if (edad >= EDAD_SOLO) {
        printf("Puede subir solo\n");
    } else {
        printf("Puede subir con un adulto\n");
    }
} else {
    printf("No puede subir\n");
}

      
Estatura (cm): 130
Edad: 10
Puede subir con un adulto

    

    

      
      
    
        
  • La pregunta por la edad solo tiene sentido si la estatura alcanzó: por eso va dentro de la rama Sí.
    • 
        
  • Cada nivel se corre cuatro espacios y cada if lleva sus llaves: se ve qué else es de quién.
    • 
      

    

  







  
 ¿Anidar o combinar?

  
Anidar o unir con &&: cuente las salidas

  

    

      Dos salidas → una decisión basta
      
if (estatura >= 120) {
    if (edad >= 12) {
        printf("Puede subir solo\n");
    }
}

      
equivale a

      
if (estatura >= 120 && edad >= 12) {
    printf("Puede subir solo\n");
}

      
Sin else interno, la versión con && es más corta y se lee mejor.

    

    

      Tres salidas → hacen falta dos decisiones
      
En la atracción, cada «no» lleva a un mensaje distinto:

      

        
no alcanza la estaturaNo puede subir

        
alcanza, menor de 12... con un adulto

        
alcanza, 12 o másPuede subir solo

      

      
Con un solo if (… && …) quedan solo dos caminos, y dos de los tres casos caerían en el mismo else. Pregunta que decide: ¿cuántas salidas distintas tiene el problema?

El else colgante: la sangría engaña, el compilador no

    printf("No puede subir\n");

No puede subir

Edad: 20

      Qué pasó
      
    
        
  • La sangría sugiere que el else es del primer if.
    •

Bloque C · El tipo char

  
Decidir con letras,
dígitos y símbolos

  
Una opción de menú, una respuesta «S» o «N», el operador de una calculadora: todo eso cabe en un char. Y un char, en el fondo, es un número.







  
 Qué guarda un char

  
Un char es un número pequeño

  

    

      
char letra = 'A';
char digito = '7';
char otra = 66;

printf("letra : %c %d\n", letra, letra);
printf("digito: %c %d\n", digito, digito);
printf("otra  : %c %d\n", otra, otra);
printf("Ocupa %d byte\n", (int) sizeof(char));

      
letra : A 65
digito: 7 55
otra  : B 66
Ocupa 1 byte

    

    

      Tres ideas
      
    
        
  • Un char ocupa 1 byte y guarda el código del carácter en la tabla ASCII.
    • 
        
  • La misma variable se muestra de dos formas: %c → el carácter; %d → su código.
    • 
        
  • '7' no vale 7: vale 55. Y un char con 66 se muestra como B.
    • 
      

      
No es un truco: para el compilador, un char es un número pequeño. Programa: char_basico.c.

 El error de char más frecuente

  
Leer un char: el Enter que quedó pendiente

  

    

      Sin espacio · leer_char_mal.c
      
scanf("%d", &edad);
...
scanf("%c", &jornada);

      
Edad: 20
Jornada (D diurna, N nocturna): Se leyo el codigo 10

      
El usuario escribió 20 y pulsó Enter. %d tomó el 20; el Enter se quedó. %c lo leyó como carácter —código 10, el salto de línea— sin esperar al usuario.

    

    

      Con espacio · leer_char.c
      
scanf("%d", &edad);
...
scanf(" %c", &jornada);

      
Edad: 20
Jornada (D diurna, N nocturna): S
Se leyo el codigo 83, que es 'S'

      
El espacio antes de %c significa «salte espacios y Enter pendientes». %d y %lf ya lo hacen solos; %c no. Úselo siempre al leer un char.

    

  

  
Ninguno de los dos programas produce advertencias: este error solo se descubre ejecutando.

Funciona porque el rango es continuo. Lo mismo para 'A'…'Z' y '0'…'9', siempre con comillas simples.

 Cierre del bloque C

  
Tres cosas que un char no es

  

    
1No es una cadena'S' y "S" son cosas distintas. Un char se compara con comillas simples (diapositiva 22).

    
2No es el número que parece'0' vale 48. c >= 0 && c <= 9, sin comillas, compila y pregunta otra cosa: los códigos del 0 al 9, que no son dígitos.

Del Según al switch

  
Cuando hay que elegir un camino según el valor exacto de un entero o de un char: su anatomía, el papel del break, los casos agrupados y cuándo conviene más un if.







  
 Anatomía

  
switch · case · break · default

  

    

      

      
    
        
  • La expresión es entera o char; cada case, un valor constante y dos puntos.
    • 
        
  • Si coincide, la ejecución empieza ahí; break sale del switch.
    • 
        
  • default = «de otro modo». Curso: siempre, de último, con break.
    • 
      


    

    

      

        C
        
switch (expresión) {
    case valor1: bloque 1; break;
    case valor2: bloque 2; break;
    default:     bloque 3; break;
}

        
Esquema compacto; en los programas, una instrucción por línea.

      

      

        Pseudocódigo (semana 2)
        
Según expresión Hacer
   valor 1: bloque 1
   valor 2: bloque 2
   De Otro Modo: bloque 3
FinSegún

        Por qué switch aquí
        
Se compara una sola variable contra valores exactos. El switch deja ver de un golpe todos los valores posibles, uno debajo del otro.

        
Con if serían siete else if, cada uno repitiendo dia == …. Los case no tienen que ir en orden, pero ordenarlos ayuda a leer.

 La caída a propósito

  
Casos agrupados

  

    

      
switch (c) {
    case 'a': case 'e': case 'i': case 'o': case 'u':
    case 'A': case 'E': case 'I': case 'O': case 'U':
        printf("%c es vocal\n", c);
        break;
    default:
        printf("%c no es vocal\n", c);
        break;
}

      
Letra: u
u es vocal

    

    

      Cuándo se permite caer
      
    
        
  • Diez case seguidos, sin nada entre ellos: todos llegan al mismo printf.
    • 
        
  • Hace lo mismo que la condición de diez partes de la diapositiva 25, y se lee mejor.
    • 
        
  • Si entre dos case hay instrucciones, cada caso termina en break.
    • 
        
  • Varios case en una línea es cuestión de estilo: lo importante es que se vea que van juntos.
    • 
      

      
Programa: vocal_switch.c. Compila sin advertencias: los case vacíos no «caen» en el sentido de la advertencia.

Dos errores de switch que el compilador detecta

  

    

      El break olvidado · advertencia
      
sin_break.c:13:13: warning: this statement may fall through [-Wimplicit-fallthrough=]
   13 |             printf("Acceso a la biblioteca\n");
      |             ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
sin_break.c:14:9: note: here
   14 |         case 2:
      |         ^~~~

      
-Wextra activa this statement may fall through en cada caso que cae al siguiente (sin_break.c produce tres, una por caso; aquí se muestra la primera). Si la caída no es a propósito, falta un break.

    

    

      El case repetido · error
      
case 'a':
...
case 97:

      
switch_duplicado.c:12:9: error: duplicate case value
   12 |         case 97:
      |         ^~~~
switch_duplicado.c:9:9: note: previously used here
    9 |         case 'a':
      |         ^~~~

      
'a' y 97 son el mismo valor: un char es un número. Un case repetido casi siempre es un error de copiar y pegar.
